Accent #cc2200 reserved for:
1. Selected option card ring: `ring-2 ring-[#cc2200]` (same pattern as BikeGallery active thumbnail)
2. Primary CTA button background (Next / Submit Inquiry): `bg-[#cc2200] hover:bg-[#a81c00]`
3. Hover state on nav links and Back button text
4. Form input focus ring: `focus-visible:border-[#cc2200] focus-visible:ring-1 focus-visible:ring-[#cc2200]`
5. Progress indicator current step highlight: font-black text in #cc2200 for the active step label

Accent is NOT used for: decorative elements, card backgrounds, hover on unselected cards, success states.

Success state color: #f2f2ee (white) text on #0a0a0a background. No green. The brand does not use green.

Source: globals.css tokens + BikeGallery active state pattern + ContactForm input focus pattern.

## Component Contracts

### 1. Page Shell (`app/configure/page.tsx`)

Server Component wrapping a single Client Component. No layout columns. Full width, max-w-2xl centered, px-4 md:px-8.

```
[Nav — sticky, inherited]
[CheckerboardStripe height=8]
[Page heading: "BUILD YOUR LAMBRE-BULL"]
[Price reference: "from AU$18,000 — AU$25,000"]
[Configurator Client Component]
[CheckerboardStripe height=8]
[Footer — inherited]
```

Page heading: h1, Barlow Condensed, text-5xl font-black tracking-tight leading-none uppercase, text-[#f2f2ee].
Price reference: text-sm Inter, text-[#888880], below heading, gap-2 from heading.

### 2. Progress Indicator

Position: above step title, below page heading, gap-lg (24px) from step title.

Spec:
- Text: `STEP {N} OF 5 — {STEP NAME}` in all-caps
- Font: Barlow Condensed, text-sm, font-black, tracking-widest, uppercase
- Current step label: text-[#cc2200]
- Step number prefix ("STEP 2 OF 5"): text-[#888880]
- Dash separator: text-[#888880]
- No progress bar. No color blocks. No dots. Text only.

Example: `STEP 2 OF 5 — MOTOR` where "MOTOR" is #cc2200 and the rest is #888880.

Step names:
- Step 1: CHASSIS
- Step 2: MOTOR
- Step 3: DISCOS
- Step 4: SOURCING
- Step 5: CONTACT + SUMMARY

### 3. Option Card (steps 1-4)

Component: shadcn `<Card>` used as a `<button>` (role="radio" or wrapping a visually hidden input).

Each option card contains:
- Card title: Barlow Condensed, text-base font-black uppercase, text-[#f2f2ee]
- Card description: Inter, text-sm, text-[#888880], line-height 1.5

States:

| State | Background | Ring | Text |
|-------|------------|------|------|
| Default (unselected) | #1a1a1a | ring-1 ring-[rgba(242,242,238,0.12)] | #f2f2ee / #888880 |
| Hover (unselected) | #2a2a2a | ring-1 ring-[rgba(242,242,238,0.20)] | #f2f2ee / #888880 |
| Selected | #1a1a1a | ring-2 ring-[#cc2200] | #f2f2ee / #f2f2ee |
| Selected + hover | #1a1a1a | ring-2 ring-[#cc2200] | #f2f2ee / #f2f2ee |
| Disabled | #1a1a1a | ring-1 ring-[rgba(242,242,238,0.06)] | opacity-40 |

Selected state indicator: in addition to red ring, a `<Check>` Lucide icon (16px, #cc2200) appears top-right inside the card. This is the only icon used in the configurator steps.

Grid layout:
- Mobile: 1 column, full-width cards, stacked
- Tablet (md): 2 columns, grid-cols-2
- Desktop (lg): 2 columns (max 3 if 3+ options per step). Do not use 4-column grids for option cards.

Card padding: py-4 px-4 (inherited from shadcn Card). Minimum card height: 80px.

Transition: `transition-all duration-150` on ring and background.

### 4. Navigation Buttons (Back / Next)

Position: below option cards grid, gap-xl (32px) from last card row. Sticky-bottom on mobile.

Desktop layout:
```
[← Back]                    [Next: {Step Name} →]
```
Justify: `justify-between`. If Step 1 (no back): Back button is hidden (not disabled — removed from DOM).

Mobile layout: full-width stacked, Next above Back (primary action first).

Back button:
- Variant: ghost (no background)
- Text: "← Back" (literal left arrow character, not Lucide)
- Barlow Condensed, text-sm, font-black, uppercase, tracking-widest
- Default: text-[#888880]
- Hover: text-[#cc2200]
- Min height: 44px

Next button (steps 1-4):
- Background: #cc2200, hover: #a81c00
- Text: "NEXT: {STEP NAME} →" (e.g. "NEXT: MOTOR →")
- Barlow Condensed, text-sm, font-black, uppercase, tracking-widest, text-[#f2f2ee]
- Min height: 44px, min width on desktop: 200px
- Disabled when no option selected in current step: opacity-40, cursor-not-allowed

Step 5 Submit button:
- Background: #cc2200, hover: #a81c00
- Text: "SUBMIT INQUIRY"
- Disabled while pending: opacity-40, cursor-not-allowed
- Pending text: "SENDING..."
- Same Barlow Condensed specs as Next button

### 5. Step 5 — Contact + Summary

Layout (two-zone stacked, single column):

**Zone A — Configuration Summary** (top)
- Heading: "YOUR BUILD" — Barlow Condensed, text-3xl font-black uppercase, text-[#f2f2ee]
- Container: bg-[#1a1a1a], rounded-sm, border border-[rgba(242,242,238,0.12)], p-6
- Each row: `<Separator>` between items (separator color: rgba(242,242,238,0.12))
- Row layout: label left, value right (flex justify-between)
- Row label: Inter, text-sm uppercase tracking-widest, text-[#888880]
- Row value: Barlow Condensed, text-base font-black uppercase, text-[#f2f2ee]
- Edit link per row: "CHANGE" text-[#cc2200] text-sm uppercase tracking-widest — clicking jumps to that step (free nav D-03)
- Price reference at bottom of summary: "AU$18,000 – AU$25,000" — text-[#888880], text-sm

Summary rows (in order):
```
CHASSIS     | [selected value]     | CHANGE
MOTOR       | [selected value]     | CHANGE
DISCOS      | [selected value]     | CHANGE
SOURCING    | [selected value]     | CHANGE
```

**Zone B — Contact Form** (below, gap-lg 24px from Zone A)
- Heading: "YOUR DETAILS" — Barlow Condensed, text-3xl font-black uppercase
- Fields: Name (required), Email (required), Message (optional)
- Field styling: identical to ContactForm (contact-form.tsx) — bg-[rgba(242,242,238,0.06)] border border-[rgba(242,242,238,0.12)] focus-visible:border-[#cc2200] focus-visible:ring-1 focus-visible:ring-[#cc2200]
- Labels: Inter text-sm uppercase tracking-widest text-[#f2f2ee]
- Error text: text-sm oklch(0.65 0.22 27)
- Message field: rows=4 (shorter than contact page — message is optional here)

### 6. Success State

Triggered: after successful Server Action response. Replaces the entire wizard (steps + nav buttons). Confirmation on same page (D-13).

Layout:
```
[CheckerboardStripe height=8]

[Success heading: "INQUIRY SENT"]
[Sub-copy]
[Configuration summary — same Zone A format]
[Return link]

[CheckerboardStripe height=8]
```

Success heading: Barlow Condensed, text-3xl font-black uppercase, text-[#f2f2ee].
Sub-copy: "We've received your custom build inquiry and will be in touch shortly."
Inter, text-base, text-[#888880], line-height 1.5.

Configuration summary in success state: identical Zone A format (read-only, no CHANGE links).

Return link: "← Back to Bikes" — ghost, text-[#cc2200] hover:text-[#a81c00], Barlow Condensed text-sm uppercase tracking-widest. Links to `/`.

No confetti. No animated checkmarks. No green. The brand aesthetic is cool and understated.

### 7. Free Navigation (D-03)

Clicking a previous step indicator OR a "CHANGE" link in the summary navigates back to that step WITHOUT resetting selections already made.

Visual contract for step indicators that are completed vs. active vs. locked:
- Completed step (user has made a selection): text-[#f2f2ee], clickable, cursor-pointer
- Active step (current): text-[#cc2200], non-clickable (already here)
- Future step (not yet reached): text-[#888880], cursor-not-allowed (clicking does nothing)

This state is managed by `useState` in the wizard client component. No router navigation between steps.

## Transitions and Animations

Library: tw-animate-css (CSS only, no framer-motion per REQUIREMENTS.md).

| Transition | Trigger | Animation | Duration |
|------------|---------|-----------|----------|
| Step content change | Next / Back click | `animate-in fade-in-0 slide-in-from-right-4` (Next), `animate-in fade-in-0 slide-in-from-left-4` (Back) | 150ms |
| Card selection | Click on option card | Ring color change via `transition-all duration-150` | 150ms |
| Button hover | Hover on Next/Submit | `transition-colors duration-150` | 150ms |
| Success state appearance | After successful submit | `animate-in fade-in-0 duration-300` | 300ms |

Step transition implementation note: apply the animation class to a `key`-driven React element so the fade fires on every step change. Example: `<div key={currentStep} className="animate-in fade-in-0 slide-in-from-right-4 duration-150">`.

No skeleton loaders. No spinner overlays. Button pending state is sufficient feedback for the Server Action call (useFormStatus `pending`).

## Mobile Responsive Behavior

| Breakpoint | Behavior |
|------------|----------|
| Mobile (< 768px / md) | Single column option cards. Navigation buttons full-width, stacked (Next above Back). Progress indicator wraps to two lines if needed. Summary rows stack label above value. |
| Tablet (>= 768px) | Two-column option card grid. Buttons side-by-side (Back left, Next right). |
| Desktop (>= 1024px) | Two-column option card grid. Wizard content max-w-2xl centered. Nav buttons side-by-side. |

Sticky navigation on mobile: Back + Next buttons fixed to bottom of viewport (`fixed bottom-0 left-0 right-0 bg-[#0a0a0a] border-t border-[rgba(242,242,238,0.12)] p-4 flex flex-col gap-2`). On desktop: static, inline with content.

## Accessibility

- Each option card: `role="radio"` within a `role="radiogroup"`, or `<button>` with `aria-pressed`. Do not use `<div>` for clickable cards.
- `aria-label` on each card: e.g. `aria-label="Select chassis: 1966 TV 200"`.
- `aria-live="polite"` region for server error messages (same pattern as ContactForm).
- Back button hidden from DOM on Step 1 (not `display:none` — `{currentStep > 1 && <BackButton />}`).
- Next button `aria-disabled="true"` when no selection made (not the HTML `disabled` attribute — to keep it focusable for screen readers).
- Progress indicator wrapped in `<nav aria-label="Configurator progress">`.
- Success state: focus moved to success heading on appearance (`useEffect` + `ref.current?.focus()`).
- Minimum touch target: 44px height for all interactive elements.
